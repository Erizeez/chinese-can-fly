# “中国人能飞” (Chinese Can Fly / CCFly)
## 面向高阶飞行爱好者的专业级 iOS 航空传感器融合与飞行黑匣子系统

---

### 一、 产品愿景与定位

在日常航空出行或通用航空飞行中，大部分普通用户只能依靠民航客舱前方的低画质航线图（Airshow）或在落地后使用商业航旅软件查看粗略的航迹回顾。然而，高阶飞行爱好者（民航常旅客、通航飞行员、滑翔伞/热气球飞行员、模拟飞行极客、航空拍客）对于**真实飞行力学数据、客舱增压规律、离线空域与跑道对正、起飞与着陆过载分析**有着极为严苛且硬核的追求。

**“中国人能飞” (Chinese Can Fly)** 是一款专为 iOS 设计的纯端侧、低功耗、全离线可用、具备民航黑匣子级传感器融合精度的专业飞行记录与态势感知工具。

### 三、 模块深度技术设计

#### 1. 航班数据模块 (Flight Data)

在客舱高空断网、飞行模式或机场起降阶段，数据获取有其特殊性。因此采用**“三层梯次数据源架构”**：

- **第一层：全离线航线预置库（Offline Static Flight Database）**
  - **覆盖内容**：国内主要航空公司（国航、东航、南航、海航、川航、厦航、春秋、吉祥等）的主力航线、航班号规则、起降机场对（Origin-Destination）、标准巡航航路与大圆距离。
  - **使用方式**：用户在无信号或机舱飞行模式下，输入航班号（如 `CA1501`）或选择出发地/目的地（如 `PEK -> SHA`），系统瞬间检索出预计飞行距离、磁航向、大圆航线航路点（Waypoints）及航向角。
- **第二层：在线开放航班数据源集成（Online Flight Feeds）**
  - **OpenSky Network API**：全球科研级开放 ADS-B 接收网络，免费 RESTful API / WebSocket，支持获取航空器 24 维状态向量（位置、气压高、几何高、地速、垂直速度、转弯率等）。
  - **ADS-B Exchange API (RapidAPI)**：未经过滤的真实原始数据，适合极客追踪特殊机型或公务机。
  - **AviationStack / FlightAware AeroAPI**：支持起降状态、登机口、行李转盘、执飞机型（如 A350-900 / B787-9）及注册号（B-XXXX）。
- **第三层：高空离线航路推算与大圆投影（Airborne Dead-Reckoning & Great-Circle Projection）**
  - 在完全脱网且无外部信号时，基于已起飞机场与到达机场的大圆航线方程（Spherical Trigonometry），结合机载 GNSS 经纬度解算出垂直偏航距离（Cross-Track Distance）、沿航线距终点剩余里程及预计到达时间（ETA）。
  - 支持航路点（Waypoints）离散插值，使航迷在断网状态下也能清晰掌控巡航剖面进度。

#### 2. 地图与机场跑道模块 (Offline Map & Aerodrome Layout)

##### 2.1 离线地图数据源调研与选型
航空场景下机舱内绝大多数时间无蜂窝网络，高空即使连上机上 WiFi 也会对地图瓦片限速。必须实现**100% 离线矢量地图**。

1. **底图边界与地理要素源：**
   - **自然地球 (Natural Earth)**：提供全球 1:10m / 1:50m 比例尺的国家与中国省份边界、海岸线、大江大河、湖泊。体积极小（中国区域仅约 15~30MB）。
   - **OpenStreetMap (OSM) 矢量切片**：中国各省份区域级 MBTiles（通过 Protomaps 或 Planetiler 生成，滤除冗余建筑细节，仅保留水体、省市行政边界、山脉标高）。
2. **机场与跑道精准数据源：**
   - **OurAirports 开源数据库 (CC0 / Public Domain)**：
     - `airports.csv`：全球 70,000+ 机场代码（ICAO 如 ZBAA、IATA 如 PEK）、标高（Elevation ft）、城市、经纬度。
     - `runways.csv`：详尽记录跑道号（如 36L/18R）、长度（Length ft）、宽度（Width ft）、表面材质（Asphalt/Concrete）、跑道头阈值坐标（Threshold Lat/Lon）、灯光系统等。
   - **OSM 航空专用图层（Aeroway Tags）**：
     - 利用 Overpass API 提取中国境内所有民用及通用机场的跑道面多边形（`aeroway=runway`）、滑行道（`aeroway=taxiway`）、停机坪（`aeroway=apron`）与航站楼轮廓（`aeroway=terminal`）。
   - **数据本地化与离线打包**：
     - 预处理将全国 250+ 民用运输机场及 400+ 通用机场的跑道拓扑压缩为 FlatBuffers 或本地 SQLite 空间表，单机体积仅不到 5MB。

##### 2.2 离线渲染技术方案
- **渲染引擎选型**：采用 **MapLibre Native for iOS (Metal)**。
  - 优势：原生地图渲染、60/120fps 高刷、支持全本地 MBTiles/PMTiles 瓦片离线加载、支持自定义 OpenGL/Metal 着色器样式的“航空暗黑夜盘仪表风”。
- **空域与进近可视化**：
  - 跑道中心线延伸虚线（Extended Centerline，5nm / 10nm 进近延长线）。
  - 飞机当前航向在地图上的实时矢量线投影、盲降下滑道（Glidepath 3°）几何截获指引。

#### 3. 飞行数据与航空级传感器融合 (Flight Telemetry & Avionics Sensor Fusion)

这是本应用最硬核的技术壁垒。充分挖掘 iPhone 14/15/16/17/18 Pro 配备的航空级微机电传感器（双频 GNSS、高动态范围 6 轴 IMU、气压计、磁力计）。

##### 3.1 核心航空物理特性：客舱增压与双高解耦
- **客舱增压悖论**：
  - 民航客机巡航高度通常在 30,000~41,000 英尺（FL300~FL410），但客舱是密闭加压结构，巡航时机舱内气压通常相当于海拔 6,000~8,000 英尺（空客 A350 / 波音 787 复合材料机身通常维持在 6,000 英尺，老款机型约 8,000 英尺）。
  - **突破性设计**：如果直接用普通天气气压公式计算手机高度，得到的将是“客舱高度”（Cabin Altitude），而非飞机真实高度！
  - **“双高度双升降率系统”**：
    1. **飞机真实飞行高度与几何升降率**：由双频 GNSS（WGS84 椭球高 + EGM96 大地水准面高）通过卡尔曼滤波输出，反映飞机在空中的真实绝对海拔与飞机真实升降率（True FPM）。
    2. **客舱环境增压监测系统**：通过 iPhone 内置气压计（Barometer / CMAltimeter）实时采样，利用标准大气公式计算客舱等效高度、客舱气压（hPa）以及客舱爬升/下降率（Cabin VSI）。
    3. **增压系统阶段识别**：自动分析客舱增压控制器的运作模式（地面预增压 -> 爬升增压 -> 巡航压差平衡 -> 进近减压至着陆场面气压）。

##### 3.2 坐标系自适应正交对准 (Aircraft Body Frame Leveling)
- **问题**：旅客在客舱内手机摆放是随机的（平放小桌板、倾斜插在前方座椅网兜、手持拍摄窗外）。
- **算法解法**：
  - 测量机身滑行起步阶段的纵向直线加速度向量 $\vec{a}_{acc}$ 与重力向量 $\vec{g}$。
  - $\vec{g}$ 方向定义为飞机机体下方向（Z-down）。
  - 在直线滑跑加速时（结合 GPS 航向角率 $\dot{\psi} \approx 0$），加速度沿飞机纵轴增加，叉乘重力向量求出横向 Y 轴（右向），再正交化求出纵向 X 轴（机头朝向）。
  - 计算从手机本体坐标系（Sensor Frame）到飞机机体坐标系（Aircraft Body Frame）的旋转四元数 $q_{sensor}^{aircraft}$。
  - 实现“无论手机以任何奇葩姿态放置，姿态仪和过载曲线均始终显示飞机的真实前后滚转、俯仰与上下 G 值”！

##### 3.3 扩展卡尔曼滤波 (GNSS-aided INS EKF)
- **状态向量**：
  $$X = [p^n, v^n, q, b_a, b_g]^T \in \mathbb{R}^{16}$$
  包含导航坐标系下的三维位置 $p^n$、三维速度 $v^n$、姿态四元数 $q$、加速度计零偏 $b_a$ 与陀螺仪零偏 $b_g$。
- **高频预测（50~100Hz）**：利用 CoreMotion 的加速度计与陀螺仪进行高频捷联惯导（SINS）机械编排积分。
- **观测更新（1Hz）**：当 GPS 双频信号有效时，利用 GPS 速度与位置进行松耦合卡尔曼更新，在线修正零偏；
- **纯惯导死推算（Dead Reckoning）**：当飞机穿越厚云层、靠近机舱内侧走道导致 GPS 短暂失锁时，EKF 自动进入死推算模式，依靠惯导维持连续位置推算与姿态仪稳定显示。

##### 3.4 航空黑匣子专业图表化
- **过载曲线（G-Load History）**：
  - 起飞抬轮（Rotation）瞬间拉起过载（通常 1.15G ~ 1.25G）。
  - 接地过载（Touchdown G-spike）：通过 50Hz 采样瞬态加速度，捕获触地瞬间的主轮过载冲击（如 1.2G 轻着陆 vs 1.6G+ 较重着陆）。
  - 接地垂直下沉率（Touchdown FPM 触地垂直速度，单位英尺/分钟）。
- **空中颠簸与湍流指数（Turbulence EDR - Eddy Dissipation Rate）**：
  - 实时分析垂直加速度高频振动功率谱（0.1Hz ~ 2Hz 带通滤波），输出 ICAO 标准轻度/中度/严重颠簸指数。
- **虚拟飞行主仪表（PFD - Primary Flight Display）**：
  - 航空级人工地平仪、俯仰标尺、滚转指针、空速/地速带、高度带、垂直速度指针（VSI 指针）。

#### 4. 后台严格保活与断电保护机制 (Background Resilience)

民航长途飞行动辄数小时，iOS 系统的后台管理极其激进，若无针对性底层设计，App 进入后台或息屏几分钟即会被系统挂起或因内存/能耗被杀。

##### 4.1 CoreLocation 航空模式深度配置
- `locationManager.allowsBackgroundLocationUpdates = true`
- `locationManager.showsBackgroundLocationIndicator = true`
- `locationManager.pausesLocationUpdatesAutomatically = false`（**致命关键点**：iOS 默认在速度无突变时会自动暂停定位，必须强制关闭）。
- `locationManager.activityType = .airborne`（启用 Apple 专门针对航空场景优化的定位管道，支持多普勒频移高速高动态滤波）。
- `locationManager.desiredAccuracy = kCLLocationAccuracyBestForNavigation`。

##### 4.2 复合后台引擎与心跳维持
- **主驱动泵**：GPS 持续位置事件回调驱动主事件循环。
- **辅助驱动（关键阶段高精度黑匣子模式）**：
  - 在起飞滑跑（速度超过 30 节）到爬升至安全高度，以及进近（低于 3000 英尺）至着陆滑行阶段，App 自动触发“关键阶段黑匣子记录”。
  - 借助配置了 `.playback` + `.mixWithOthers` 的微底噪音频会话（Audio Session），保持 CoreMotion 50Hz 高刷不断流，毫秒级捕获接地冲击。
- **平飞自适应节能降频**：
  - 当巡航平飞超 10 分钟且无明显机动时，惯导自动降至 1Hz~5Hz，降低发热与电量消耗。

##### 4.3 零丢失断电保护存储架构（WAL Engine）
- 采用 **SQLite WAL (Write-Ahead Logging)** 或结构化二进制流日志（Binary Flight Log）。
- 每 1 秒刷新脏页，即使飞机落地后手机完全没电关机，已记录的数小时航迹与传感器数据 100% 完整，无损自愈。

#### 5. 设置与工具箱模块 (Settings & Toolbox)

- **机体轴校准向导**：进入机舱坐定后，一键“零位校准 / 机头方向指定”。
- **传感器采样频率设置**：高精度极客模式（50Hz）、平衡模式（10Hz）、长航时省电模式（1Hz）。
- **离线数据包中心**：
  - 全国基础地形与省界包（~25MB）。
  - 全国机场与跑道拓扑包（~5MB）。
  - 高精度高程 DEM 阴影包（可选按需下载）。
- **航空单位体系切换**：
  - 航空标准制：高度（英尺 ft）、速度（节 kts）、距离（海里 NM）、气压（百帕 hPa / 英寸汞柱 inHg）。
  - 国际公制：高度（米 m）、速度（公里/小时 km/h）、距离（公里 km）。
- **专业日志导出**：
  - **GPX**（含高精几何高与时间戳，无缝导入 Google Earth / 两步路）。
  - **KML 3D 飞行航线**（在 Google Earth 中呈现 3D 彩色高度带）。
  - **CSV 原始传感器数据**（方便科研与数据分析爱好者导入 Python/MATLAB 分析过载频响）。
  - **IGC 格式**（国际航空联合会 FAI 标准滑翔与飞行日志格式）。

### 四、 技术栈与工程落地规划

- **语言与平台**：Swift 6, iOS 17.0+ (适配 iPhone 15/16/17/18 Pro 硬件特性)
- **界面架构**：SwiftUI + 响应式 MVVM + Observation 框架
- **图形渲染**：
  - 地图：MapLibre Native iOS (Metal 硬件加速)
  - 仪表/姿态：SwiftUI Canvas + Metal 着色器
  - 曲线：Swift Charts (支持动态超大数据集平滑渲染)
- **算法核心**：Accelerate.framework (vDSP/LAPACK 矩阵快速运算，用于 EKF 协方差更新)
- **存储引擎**：SwiftData / SQLite3 C-API with WAL
